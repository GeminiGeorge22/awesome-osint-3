# Contributing

Thanks for helping improve this list. Quality beats quantity: a short list of reliable, well-described resources is more useful than a long one.

## What belongs here

An entry must be:

- **Legitimate and publicly available** - an official project page, repository or publisher page.
- **Useful for lawful work** - authorized security assessments, journalism, academic research or investigations.
- **Maintained** - actively developed, or still widely used and working.
- **A primary source** - link to the tool or author, not to a blog post or affiliate page about it.

## What does not belong here

Pull requests will be closed if the resource's main purpose is to:

- Stalk, track, harass or dox private individuals (including people-search and "find anyone" services).
- Sell, trade or search leaked or breached personal data.
- Deanonymize people without a lawful basis (for example, face-matching private individuals).
- Bypass authentication, paywalls or platform terms of service.

When in doubt, open an issue first and explain the legitimate use case.

## Entry format

```markdown
- [Name](https://official-link) - One-line description ending with a period.
```

- Use ` - ` (space, hyphen, space) between the link and the description.
- Keep the description short, factual and free of marketing language.
- Mention if the tool is commercial or requires an account, when it is not obvious.
- Add the entry to the most specific section; keep the existing order within the section.
- Do not use real people as examples in descriptions.

## Pull requests

1. One resource (or one closely related group) per pull request.
2. Check that the link resolves. CI runs [lychee](https://github.com/lycheeverse/lychee) on every pull request.
3. Explain in the PR description why the resource is useful and how it fits the ethics notice.
4. Make sure your commits do not contain personal data or secrets.

By contributing you agree to release your contribution under [CC0-1.0](LICENSE).
